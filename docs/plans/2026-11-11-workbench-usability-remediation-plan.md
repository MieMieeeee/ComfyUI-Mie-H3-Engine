# 工作台功能与用户便利性整改计划

- 日期为 2026-11-11，核对基线为 `a2504c3`。
- 状态为待实施，所有任务框均为待办。
- 本计划覆盖评审中的 F01–F08、U01–U08，共 16 类问题。
- 原评审运行了 236 项测试且全部通过，该结果作为整改前基线。后续完成状态以新增验收和实际执行结果为准。
- 总体架构服从 [项目总计划](../../PLAN.md)，本功能延续 [图文起草计划](2026-11-11-storyboard-intake-plan.md)。复现证据见 [用户便利性评审](../../notes/review-ux-intake-20261111.md)。

## 1. 交付目标

用户在作出制作决定前，能够看清人物、听到实际声音样本、确认剧本与参考资产，并能在返回、刷新和跨页面操作后继续工作。页面显示、提交参数、资产保存结果和实际制作输入应一致。

本次整改沿用现有工作台页面、资产格式、生成器与契约校验。新增操作接入既有保存、版本和制作链路，正式写入继续由明确的保存或制作动作触发。

## 2. 执行顺序与交付门槛

| 批次 | 范围 | 交付门槛 |
| --- | --- | --- |
| A 起草可靠性 | F01–F05、U05 的参数一致性 | 实际实例可用，确认内容正确，返回与刷新均可继续 |
| B 试听与制作准备 | U01、U03、F08 | 详情、上传与选角均可试听，媒体缺项在提交前定位 |
| C 参考资产闭环 | F06、F07、U02 | 新建安全、目标可读回，场景能够进入真实制作计划 |
| D 编辑与制作衔接 | U04、U05 的故事摘要、U07 | 保存并制作、返回恢复配置、模型设置与起草接通 |
| E 历史与窄屏 | U06、U08 | 作品和尝试可辨认，常用操作在窄屏可完成 |

批次顺序为 A → B → C → D → E。每批完成后提交可审阅的改动与对应证据，最终按第 8 节完成整条用户旅程验收。

## 3. 批次 A · 起草可靠性

### A1 · F01 · 对齐运行版本

- [ ] 核对 8199 端口对应进程、工作目录和加载版本。重启前核对在途任务及既有恢复逻辑，按当前启动方式更新工作台实例。
- [ ] 增加进程启动时的版本标识，并让页面资源与该版本对应。健康检查可核对运行版本，新路由与关键模板纳入启动后检查。
- 验收要求从实际工作台地址打开 AI 起草，再用角色事件文本完成解析。后端、模板和静态资源版本一致，重启不会重复提交已有任务。

### A2 · F02 · 修正事件角色下拉显示

- [ ] 调整动态角色选项与事件选中值的绑定时序，使下拉显示、事件对象和提交角色一致。
- [ ] 检查恢复、复制事件、排序及角色增删后的绑定，保留稳定的界面引用。
- 验收输入小明和小红的两条台词，第二条始终显示并提交小红。测试同时读取可见选项与实际请求数据。

### A3 · F03 · 将图片理解接入引导设计

- [ ] events 请求包含用户确认的图片信息、创作建议、人工补充与冲突裁定，同时保留原文用于台词保护。
- [ ] 支持纯图片和人工图注进入角色、事件与整体设计。区分图片事实、创作补充和需保留的台词。
- 验收纯图、图文、图注和手动冲突裁定均能进入下一步。确认过的信息在事件或设计字段中有对应，原台词保护继续生效。

### A4 · F04 · 恢复草稿后自动预检

- [ ] 事件草稿恢复完成后自动发起预检，状态依次显示等待、通过或具体错误。
- [ ] 保留重试入口，并处理恢复过程中内容变化产生的迟到响应。
- 验收刷新后点击继续草稿，无需手动寻找“重新预检”即可继续生成或定位错误。

### A5 · F05 · 返回时保留人工编辑

- [ ] 返回素材步骤时保留角色、事件、排序和补写采用状态，相关校验标记为待重新确认。
- [ ] 重新整理展示已有编辑与新建议的差异，用户选择采用。提供明确的重新开始动作来清空内容。
- 验收修改台词、增删角色和排序后返回，再进入时改动仍在。素材变化后仍可回看上一份事件稿。

### A6 · U05 · 显示实际生效的起草参数

- [ ] 将分镜数量的 0 明确显示为“自动”，核对 concept 与 script 调用，消除界面显示 0 而请求变成 2 的隐式替换。
- [ ] 生成前摘要说明时长、分镜数及文字规则的实际含义，区分可调整偏好和已确认约束。
- 验收分别检查两种生成路径的页面值、请求参数及生成器接收值，三者对应。

## 4. 批次 B · 试听与制作准备

### B1 · U01 · 三处统一提供音色试听

- [ ] 角色详情列出全部已有声音样本，提供播放、暂停、定位、重播、样本序号与时长。核实并显示引擎实际使用样本的规则。
- [ ] 新选音频后先提供本地试听，显示将替换的样本，保存前允许撤销本次选择。
- [ ] 制作页选角后展示图片、声音描述和样本试听，用户可在同一张角色卡核对形象与声音。
- [ ] 无样本时显示“暂无声音样本”和上传入口。只有文字描述时准确显示当前素材状态。
- [ ] 复用统一播放状态，同一时间播放一个样本。切换角色、替换文件或关闭预览时停止旧播放并释放本地文件引用。
- 验收覆盖已有样本、新上传、多样本、无样本、加载失败及切换角色。声音资源按需加载，播放器可通过键盘操作。

本批交付以真实音频样本试听为准。模型合成试听列为后续扩展，接入前需明确模型能力、调用费用和与最终配音的关系。

### B2 · U03 · 完善图片预览与媒体改动保护

- [ ] 详情展示全部图片的缩略图，支持放大查看。编辑时可比较现有媒体与待保存媒体。
- [ ] 新建与编辑分别显示准确的必填项和保留规则，将媒体选择、替换及撤销计入未保存状态。
- [ ] 只更换图片或音频时，切换资产、取消或离开页面也有明确的改动保护。
- 验收只替换媒体后离开时能得到正确反馈，取消离开后选择仍在，保存失败保留输入。首次创建的缺项在表单上可见。

### B3 · F08 · 提交前检查真实制作条件

- [ ] 扩展现有计划预览，按实际配音模式、角色出镜情况和计划要求检查资产及媒体。参考配音检查可用声音样本，图片需求服从核心计划。
- [ ] 在角色卡片上显示缺项及补齐入口，提供检查中、通过、缺项和检查失败状态。
- [ ] 将 ComfyUI 连接状态与有效预检结果纳入提交条件。输入或绑定变化后，使旧预检结果失效。
- [ ] 服务端排队前再次校验当前输入，防止预检后资产变更造成状态不一致。
- 验收缺参考音、资产损坏、必要图片缺失和连接失败都能在提交前定位，失败检查不会产生渲染任务。

## 5. 批次 C · 参考资产闭环

### C1 · F06 · 同名资产保存前明确处理

- [ ] 新建和另存入口默认采用创建语义，同名时提示改名。支持覆盖时展示现有资产与将替换内容，由用户明确选择。
- [ ] 服务端提供原子的重名拒绝与明确覆盖语义，避免检查后写入之间的竞争。已有编辑请求继续支持更新。
- 验收同名角色和场景在用户决定前均不会被改写。连续点击或重复请求得到一致结果，保存失败保留表单。

### C2 · F07 · 保存并读回参考目标

- [ ] 提交前组装唯一的描述字段，确保参考目标实际入库，并在成功回执或详情中读回确认。
- [ ] 多人物图提供区域裁剪与全图预览，用户确认目标区域后保存。沿用全图时显示实际保存内容和目标说明。
- 验收目标内容保存后仍在，保存图片与用户预览一致，后续资产页可查看。裁剪和取消均保留起草原图。

### C3 · U02 · 将场景参考接入制作

- [ ] 根据剧本场景需求提供场景资产选择、缩略图、放大查看、描述和环境音说明，并明确被覆盖的剧本字段。
- [ ] 为制作接口增加兼容旧请求的场景绑定，将选择传递到真实计划和工作流。接入任务记录、配置恢复及既有输入追踪机制。
- [ ] 从起草另存场景后，提供直达资产与后续制作的入口，反馈当前引用状态。
- 验收完成“起草图 → 另存场景 → 制作选择 → 计划使用”的闭环。旧剧本、旧任务和缺省场景绑定仍可读取。

## 6. 批次 D · 编辑与制作衔接

### D1 · U04 · 保存并制作、配置恢复与再做一版

- [ ] 有未保存修改时提供“保存并制作”，保存成功后带明确剧本版本进入制作。保存失败留在当前编辑稿。
- [ ] 暂存制作会话的剧本版本、角色与场景绑定、画幅及参数。去资产页补素材或模型页配置后，返回可继续。
- [ ] 恢复时检查资产、剧本及版本是否可用，明确标出变化，防止恢复到无效绑定。
- [ ] 历史提供“用本次配置再做一版”，使用新运行名和版本。保留“从这次继续”的续跑语义，并显示复用输入的实际状态。
- 验收编辑后的内容确实成为制作输入，跨页面补声音后配置仍在，再做一版产生独立运行。

### D2 · U05 · 补上故事确认摘要

- [ ] 引导路径展示可编辑的一句话故事摘要，以及人物、地点和画面偏好的确认内容。
- [ ] 摘要、角色事件和整体设计之间的修改可追踪，生成时使用本次确认值。为英文制作术语补充简明中文用途说明。
- 验收用户可在生成前说明这一版在讲什么，改过的摘要和设计进入实际请求，事件锁定规则仍然明确。

### D3 · U07 · 起草区展示模型状态并接通设置

- [ ] 起草区展示当前平台、模型及可靠的视觉能力状态，能力未知时准确表达。
- [ ] 未配置或连接失败时提供直达设置入口，返回后保留素材和步骤。首次配置优先引导完成一个平台。
- [ ] 切换模型后使相关能力检查和在途请求失效，保留用户已经确认的内容。
- 验收未配置、不能看图、正常模型和切换模型四种情况均有明确下一步，凭据仅由现有设置机制处理。

## 7. 批次 E · 历史与窄屏

### E1 · U06 · 清楚展示作品、尝试和结果

- [ ] 按作品运行组织尝试记录，成片归到所属运行，展开查看各次尝试时间、状态及错误。
- [ ] 搜索、筛选、分页和计数使用一致的作品集合，并清楚显示作品数与尝试次数。
- [ ] 保留播放、下载、收藏和版本入口，增加当前页的声音试听及分镜片段切换。复用 B1 的播放管理。
- [ ] 核对分组后的续跑、再做一版和删除作用范围，保持既有任务与产物归属保护。
- 验收同一运行的中断与成功尝试归属清楚，用户能找到成片和对应配置，分页不会拆散或重复计算作品。

### E2 · U08 · 让窄屏用户直接进入操作区

- [ ] 打开起草或编辑后滚动到操作区并设置合理焦点，窄屏剧本列表收为选择入口。
- [ ] 压缩恢复提示的首屏占用，保留继续与清空动作。事件编辑和错误跳转后保持当前位置。
- [ ] 检查资产播放器、制作选角卡片、模型设置和历史操作在窄屏的可访问性。
- 验收在约 390 像素宽和桌面约 1440 像素宽完成核心旅程。无意外整页横向溢出，主要按钮可见、可触达，键盘可完成主要操作。

## 9. 预计修改位置

| 位置 | 职责 |
| --- | --- |
| `webapp/flask_app.py` | 健康版本、媒体读取、资产创建语义、预检和制作接口 |
| `webapp/services/intake.py`、`autodraft.py` | 已确认图片理解进入事件整理、内容与参数校验 |
| `webapp/services/library.py` | 音频样本元数据与资源、创建冲突、参考目标保存 |
| `webapp/services/workflow.py`、`runner.py`、`snapshot.py` | 场景绑定、提交前校验、配置与输入记录 |
| `webapp/services/history.py` 及现有任务查询逻辑 | 作品与尝试组织、搜索与分页 |
| `webapp/static/app.js` | 表单绑定、状态恢复、统一播放、配置交接、版本保护 |
| `webapp/templates/`、`webapp/static/app.css` | 资产、起草、制作、设置和历史的操作入口与响应式布局 |
| 现有工作台启动入口 | 实例版本对齐与启动后检查 |
| `webapp_tests/` | 服务层与页面回归，复用现有临时资产库和模型替身 |

实施时依据实际依赖选择最小修改范围，先复用现有逻辑，再决定是否拆分共享媒体组件或服务。旧资产、多样本资产、旧任务和缺少新增字段的历史记录均纳入兼容验证。

## 10. 完成标准

F01–F08 与 U01–U08 的任务和对应验收全部完成，实际工作台加载已验收版本，用户能够完成“起草 → 确认 → 保存 → 试听选角与场景 → 制作 → 查看结果 → 再做一版”。每批交付记录包含提交、测试结果与页面证据，遗留项明确回填到本计划。
