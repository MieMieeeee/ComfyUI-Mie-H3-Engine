# 图文起草与引导式分镜设计实施计划

- 日期为 2026-11-11。
- 状态为方案已确定，实施待开始。下列任务框均表示待完成工作。
- 核对基线为提交 `3815beb` 及当前工作区。状态存储相关未提交改动须在实施前协调。
- 本文细化本功能的用户流程和交付步骤。总体架构、资产契约及项目范围服从仓库根目录的 [PLAN.md](../../PLAN.md)。

## 1. 交付目标与完成条件

用户能够从一张图片、一段文字或两者组合开始，选择快速生成或逐步确认，得到可编辑的分镜草稿。用户能够明确控制原台词是否保留，并在失败、返回、刷新后继续工作。

核心交付覆盖以下闭环。

1. 提供素材，明确图片的用途与文字的改编规则。
2. 图片解读可检查、可修改，创作补充有明确标记。
3. 快速路径生成一版，引导路径确认故事、角色和事件后生成。
4. 生成结果进入现有时间轴、分镜卡和编辑表单，检查后通过现有保存入口入库。
5. 编辑后的执行描述状态、保存版本和修订继续遵守现有流程。

完成条件以第 12 节的验收清单为准。参考资产保存作为第三阶段独立交付。

## 2. 已确定的产品决策

| 决策项 | 本次选择 | 原因与约束 |
| --- | --- | --- |
| 入口 | 扩展剧本页现有 AI 起草卡片，标题改为“从图片或文字起草” | 保持用户在同一页面完成起草和编辑 |
| 生成方式 | “直接出一版”和“一起设计”两种路径 | 分别服务快速试想法与逐步控制内容 |
| 文字规则 | 单独设置“允许改编”和“保留原台词” | 生成方式与原文保留分别表达 |
| 文本直出 | 允许改编时可直接生成，读稿按需展开 | 减少纯文字用户的等待与确认次数 |
| 图片输入 | 完成一次图片解读，展示可修改摘要，再由用户发起长生成 | 让错误识别在生成前可见 |
| 引导编辑 | 角色卡片与结构化事件列表，支持普通用户操作 | 契约格式由适配层生成 |
| 事件锁定 | 引导路径确认后的事件，以及保留台词路径确认后的事件，统一走 script 模式 | 复用核心事件约束与校验 |
| 全局画面参数 | 在事件生成前提供默认值，在确认区允许修改 | script 模式会固定这些字段 |
| 草稿保存 | 浏览器暂存起草过程，正式资产由用户点击保存 | 分清工作恢复与资产入库 |
| 图片用途 | 起草阶段用于理解故事，后续单独保存角色或场景参考 | 页面明确当前图片的作用范围 |

最初打开时默认“直接出一版”。文字规则默认“允许改编”，旁边展示“AI 可调整情节和台词”。若原文能完整解析为角色事件行，且用户尚未手动选择规则，则预选“保留原台词”并显示已识别的事件数量。后续输入变化保留用户主动选择。

曾考虑让所有输入统一经过完整读稿，这会增加纯文字用户的等待。也考虑扩展核心生成器以允许 script 模式重新决定全局画面参数，这会改变现有锁定语义。本计划复用现有两种模式，在 Web 适配层和交互层完成分流。

## 3. 页面结构与用户路径

### 3.1 起草卡片

采用逐步展开的单个工作区。上方始终保留素材缩略图、原文和当前步骤，已完成步骤可折叠并返回编辑。角色和事件较多时使用完整内容区，避免在窄卡片内嵌套滚动。

- 素材区提供单图上传、删除、替换与文字输入，至少有一项。原文独立保存。
- 生成方式并排呈现，按钮下有一句结果说明。
- 文字规则紧靠原文输入，明确当前生成允许修改哪些内容。
- 图片下固定展示“用于理解故事。视频参考图可在后续单独设置。”
- 时长、画面风格和语言先展示常用项，其余制作参数折叠。当前确认摘要展示所有最终生效值。
- 页面同时只有一个主要动作，按钮随步骤显示“解读图片”“整理角色与事件”或“生成分镜草稿”。

### 3.2 快速生成

1. 纯文字且允许改编时，用户设置基本偏好后直接生成。可选“先看看 AI 的理解”进入读稿。
2. 有图片时，先解读图片。展示图中可见信息和故事补充建议，用户可修改、删除或添加说明。
3. 图文冲突时提示具体冲突，用户选择文字为准、图片为准或手动改写对应字段。涉及人物身份和关键事件的未解决冲突须处理后继续。
4. 允许改编时，将原文、用户确认的图片摘要及画面偏好组织为 concept，调用现有概念生成。
5. 选择保留原台词时，先得到可校验事件。已经符合契约的文本可跳过 AI 整理，展示角色与事件确认摘要后生成。普通故事或混合文本进入事件确认。
6. 成功后展示草稿及“待保存”状态，提供检查问题、继续编辑和保存入口。

### 3.3 一起设计

第一步确认故事与人物。

- 一句话故事、角色、地点、故事气氛与画面风格由读稿提出，用户可以逐项修改。
- 角色卡片包括名字、画面内外、是否初始出现、位置和声音说明，映射现有角色契约。
- 场景描述进入 scene，整体世界和风格进入 setting、look，导演要求进入 constraints。字段用途通过帮助文字说明。
- 镜头景别、运动和视角提供默认预设，在“画面设置”中可修改。此处显示它们会用于本版所有镜头的全局设置。

第二步确认事件与生成条件。

- 事件行包含类型、角色、内容和语言，类型支持台词、动作、入场、离场。
- 提供新增、删除、复制、上移和下移，拖动作为补充操作。错误直接定位到具体行。
- 旁白以画外角色承载。场景和导演要求有独立入口，避免挤入台词行。
- 展示事件数、目标时长和分镜数量，预检通过后展示确认摘要。
- 主按钮为“按已确认内容生成”。确认后事件的类型、角色、文字、顺序和语言全部锁定。

第三步生成与检查。

- script 模式完成事件分镜归组、分镜时长分配和英文执行描述。
- 输出中的事件与确认稿自动比对，契约和执行描述通过校验后才能进入编辑器。
- 已确认故事、事件和本版草稿均可回看。需要调整事件时返回事件列表，重新确认后生成下一份候选结果。

## 4. 原文保留与图片解读规则

### 4.1 保留原台词

原始输入、整理后的事件稿和用户确认后的锁定稿分别保存。系统必须区分它们的用途和来源。

- 对可解析的角色事件文本，直接使用共享解析器得到事件，跳过模型改写。
- 对普通文本，整理接口返回事件建议与原文片段映射。模型提出的补写台词单独标记，默认等待用户确认。
- 用户选定需保留的原文台词后，事件内容必须与对应片段一致。只能采用共享解析器约定的首尾空白规范化，标点、数字、措辞和事件内换行处理均需明确验证。
- 无法确定哪些片段是台词时，展示原文与事件并排确认。存在尚未分配的保留片段时阻止长生成，允许用户分配、标记为场景说明或主动解除保留。
- 引导路径在确认后锁定整份事件稿。后续修订若会改动锁定事件，先展示变更并重新确认。
- 跨镜头重复或遗漏事件、台词被换词、角色串位、语言变化均视为生成失败，保留用户确认稿并提供重试。

### 4.2 图片解读

解读分为图中可见信息、创作建议和用户补充三组。可见信息使用审慎措辞，身份、关系、心理和前后剧情默认归入创作建议。各项允许修改，修改后记录为用户确认内容。

平台能力采用 supported、unsupported、unknown 三态。使用现有可靠能力信息，unknown 时允许一次正常视觉请求。明确不支持图像时返回需要图注的业务状态。认证失败、额度不足、限流和超时分别反馈并保留素材。

用户补图注后显示“根据你提供的图注”，其内容保留人工来源。更换图片后，旧图解读失效。模型切换保留已确认内容，尚未完成的视觉请求作废，下一次请求重新检查能力。

## 5. 状态、恢复与覆盖保护

起草状态采用显式步骤和内容修订号。每次素材、角色、事件或生成参数变化均递增 revision。请求携带 request_id 和发起时的 revision，响应只允许应用到相同版本的当前起草会话。

| 状态 | 用户可见内容 | 主要动作 |
| --- | --- | --- |
| material | 图片、原文、生成方式和文字规则 | 解读或直接生成 |
| reading | 素材保留，显示正在理解素材 | 取消等待 |
| understanding | 解读、来源、冲突和补充说明 | 确认理解或进入设计 |
| designing | 故事、角色和画面设置 | 整理事件 |
| events | 事件列表、原文对照和预检反馈 | 确认并生成 |
| generating | 已确认摘要、真实请求状态 | 取消等待 |
| candidate | 候选结果、校验结果和当前编辑器差异 | 载入编辑器 |
| editing | 现有编辑器与待保存提示 | 保存或修订 |

reading 和 generating 为当前步骤的忙碌状态。失败回到发起步骤并保留所有输入。取消会使该请求失效，服务端调用可能已产生费用，页面说明这一点并阻止迟到结果覆盖。

上游变化采用失效标记，用户此前的编辑仍可回看。

- 修改图片或原文后，相关解读、事件映射和预检标记为需要重新确认。已人工编辑的事件保留为上一版候选。
- 修改角色时，以稳定的界面 ID 维护引用。删除被引用角色须先处理关联事件，重命名自动同步显示。
- 修改事件、时长、分镜数或画面参数后，旧预检与生成许可失效。
- 一次有效校验只对应当前完整内容。服务端生成前重新解析和校验提交内容，前端通过标记不能替代校验。
- 生成过程中编辑器发生变化，结果进入候选区，由用户明确选择载入。编辑器为空且 revision 未变时可直接载入。切换到其他剧本后禁止自动载入。
- 双击按钮只创建一次当前页面请求。复用现有请求保护机制，避免叠加外层自动重试。

浏览器恢复采用独立的 `storyboard-intake:v1` 命名空间。文本和步骤元数据写入小型 localStorage 记录，图片 Blob 写入 IndexedDB。先完成图片写入，再发布引用它的元数据。写入失败显示“本次内容尚未暂存”，页面继续保留内存输入。

默认仅保留当前起草会话，未使用草稿七天后清理。加载时处理图片缺失、旧字段和损坏记录，允许恢复可用文字。提供继续草稿、清空草稿和图片重新选择入口。七天为本计划选定的产品默认值。

## 6. 数据与接口设计

### 6.1 起草会话字段

| 字段组 | 最低字段 |
| --- | --- |
| 会话 | schema_version、session_id、revision、step、updated_at |
| 原始素材 | original_text、image_blob_key、image_metadata、manual_caption |
| 用户选择 | flow_mode、text_policy、用户是否主动选择规则 |
| 理解结果 | observed、proposed、user_notes、conflicts、各项来源与确认状态 |
| 设计稿 | story_summary、roles、scene、look、setting、constraints、camera |
| 事件稿 | 稳定 UI ID、角色 UI ID、type、text、language、原文片段映射、确认状态 |
| 生成条件 | name、language、audio_mode、target_duration_seconds、shot_count、critic |
| 请求记录 | request_id、revision、pending_action、候选结果对应版本 |

角色和事件在界面上使用稳定 ID。提交时按当前顺序序列化为核心的 `character_N` 和 `event_NNN`，同时保存 UI ID 到核心 ID 的映射以定位错误。角色别名冲突在生成前报告。

### 6.2 新增 POST /api/scripts/intake

采用 JSON 请求，action 仅允许 `read` 或 `events`。公共字段包括 request_id、revision、原文、文字规则与模型选择上下文。read 可带归一化图片 data URL 和人工图注，events 使用已确认理解、角色和原文。

- read 返回结构化理解、来源、冲突、视觉能力状态及下一步。无法看图且缺少图注时返回 `state=needs_caption`。
- events 返回结构化事件建议、原文映射、未分配片段与补写内容。已经符合事件契约的输入先走确定性解析。
- 两种 action 分别使用专用提示词和响应 schema。图片传输复用现有多模态 `_invoke`，读图提示词围绕故事素材。
- 响应严格检查字段类型、枚举、数量和长度。异常模型输出反馈到当前步骤，保留用户已修改字段。
- API 只返回草稿数据。正式资产写入沿用现有保存接口。

### 6.3 新增 POST /api/scripts/intake/validate

输入角色、结构化事件、锁定规则和全局生成参数。服务端序列化并调用共享 `parse_roles`、`parse_script` 及适用的契约校验，返回规范化角色、事件、source_script、字段级错误和可行性反馈。此接口无需模型调用。

- 核心当前角色数量为 1–8，事件为 1–200，source_script 总长上限为 30000，单事件上限为 2000。限制取自共享契约，界面同步展示。
- script 的 shot_count 为 0 或 1–20，明确数量时不得超过事件数量。界面以“自动”表达 0。
- 事件内容必须能无损往返现有单行事件格式。含内部换行或保留规则无法表达的内容定位提示用户处理，用户确认后再拆分。
- 确定性的数量、格式、引用和时长硬约束阻止生成。语速等估计标记为估计，展示调整时长或编辑事件入口。
- 复用核心时长估算和帧分配逻辑，按其真实适用范围校验。分镜归组尚未产生时只报告可证明的限制，生成后再执行完整时长校验。

### 6.4 扩展 POST /api/scripts/auto

保留现有 concept 和 revise 请求的默认值与响应结构。新增显式 script 请求，包含角色、已确认 source_script、事件核对信息和完整全局参数。省略 mode 沿用现有默认行为，显式未知 mode 返回字段错误。

Web 服务层新增明确的 `source_script` 参数，调用核心生成器时，必须把它传给第一个位置参数 `concept`。核心当前通过 `**_unused` 接收未知参数，单独传 `source_script=` 会被忽略，应以入口测试锁住映射。

适配层将 character_count、character_settings、camera_framing、camera_movement、camera_perspective、look、setting、scene、light、light_text 和 constraints 等有效参数显式传递。使用既有生成器默认值，用户更改后以确认摘要为准。

核心 script 模式锁定角色、原事件和全局 header。模型负责分镜归组和执行描述。明确分镜数属于约束，concept 模式中的分镜数和时长偏好按现有行为执行。切换路径时页面更新参数说明。

生成前重新校验。生成后使用核心完整校验，并比较确认事件的 ID、类型、角色、文字、顺序、语言及锁定 header。失败结果保留在诊断路径，不能作为有效草稿覆盖编辑器。

新草稿中已有效生成的英文执行描述直接展示。后续编辑中文内容造成不同步时，使用既有失效标记与更新入口。

### 6.5 错误与输入边界

- 所有新响应带可识别的 code、request_id 和 revision，业务状态和调用错误分开处理。
- 参数错误返回 400，素材超限返回 413，不支持的文件类型返回 415。上游鉴权、额度和限流沿用现有适当状态映射，超时提供可重试提示。
- 不能看图采用 `needs_caption` 状态，显示补图注动作。仅将明确视觉能力错误映射到该状态。
- 本次选定单图、原始文件最大 10 MB、解码像素上限 2000 万。浏览器处理方向后转为最长边 2048 的 JPEG 或 PNG，归一化文件最大 4 MB，请求体上限 8 MB。
- 输入接受 JPEG、PNG 和 WebP，动画文件与 SVG 提示重新选择。服务端独立验证类型、字节大小、解码尺寸和实际可解码性，拒绝客户端传入的本地路径及远程抓图 URL。
- 图片默认只在请求内处理，浏览器恢复用 Blob。日志记录请求标识、状态和耗时，图片 data URL、密钥和完整台词避开常规日志。
- 图片上限为产品默认值。实施时核对当前模型限制，遇到更小限制提前提示并明确实际生效值。

## 7. 与现有编辑器、资产和制作页的衔接

起草结果沿用当前分镜资产结构。候选结果应用到编辑器前，复用现有未保存内容保护。保存继续使用剧本保存和版本入口，修订继续使用既有交互。起草会话 ID 与正式剧本 ID 分开维护，保存成功后记录关联。

通过本功能确认的事件，在编辑器提供“已确认事件”摘要。用户直接编辑事件或提交涉及台词改动的修订时，展示与确认稿的变化并更新确认状态。已有剧本的普通修订仍遵守原有请求协议。

参考资产保存独立进入第三阶段。

1. 用户点击“另存为参考资产”，选择角色或场景。
2. 展示图片与目标区域，多人物图片要求明确目标，可裁剪或沿用全图。
3. 填写名称和描述，可主动使用现有 AI 补全。
4. 复用资产页上传和保存能力，成功后展示资产入口。
5. 需要制作引用时，通过当前已有绑定流程显式选择。保存反馈说明资产已入库及当前引用状态。

## 10. 测试与回归策略

自动测试默认使用可控制的模型替身，检查真实路由到服务到核心适配的链路。真实模型验证单独显式运行，记录平台、模型、耗时与结果。

| 测试组 | 必须覆盖的情况 |
| --- | --- |
| 兼容 | 老 concept、revise 请求及缺省 mode，既有保存、版本与执行描述行为 |
| 素材 | 空输入、纯文本、纯图、图文、损坏图片、伪造类型、超大字节与解码尺寸 |
| 能力与错误 | supported、unsupported、unknown，人工图注，401、额度、429、超时分别保留输入 |
| 原文保留 | 数字标点、角色别名、语言、原文片段遗漏、补写台词、内部换行、确认后变更 |
| 引用 | 重名或别名冲突、角色重命名、删除被引用角色、事件排序后的 ID 映射 |
| 时长与数量 | 自动与明确分镜数、分镜数超过事件、事件与角色上限、可证明的时长冲突 |
| 核心调用 | script 文本进入位置参数、完整 header 传递、未知 mode 拒绝、调用前预检失败 |
| 输出校验 | 模型改台词、漏事件、重复事件、顺序变化、改角色或 header、缺少有效执行描述 |
| 异步 | 迟到读稿、迟到生成、输入变化、切剧本、双击、取消、失效响应和主动重试 |
| 暂存 | 刷新恢复、图片丢失、配额不足、损坏或旧记录、过期清理、保存后的关联 |
| 落库 | read、events、validate 和 auto 前后资产清单一致，明确保存后才新增资产或版本 |

回归必须从正常入口触发。三条关键测试分别验证 script 源文参数被忽略、生成覆盖新编辑、台词变化仍被接受这三种错误行为。对关键保护做受控负对照，临时退回错误行为后测试应失败，在隔离环境完成验证并恢复修复。

按仓库已有命令运行相关测试和全量测试。浏览器检查使用真实页面和网络请求，记录截图与关键结果。只有实际执行并通过的结果才能记入实施完成记录。

## 11. 界面与可访问性要求

- 桌面约 1440 像素宽和移动端约 390 像素宽完成核心流程，表单区域无意外横向滚动。
- 原文和事件对照在桌面并排，窄屏分区切换，切换保留编辑位置。
- 标签独立于占位符。角色、事件类型和所有主要操作可通过键盘完成。
- 上传、忙碌、成功和错误有文字状态。错误摘要可跳转到具体字段，焦点跟随步骤合理移动。
- 阅读结果、用户确认内容和补写建议通过文字标签区分，颜色作为辅助。
- 使用真实请求阶段描述等待，长生成展示已等待时间。提供取消等待和失败重试，保留可见输入。
- 用户改过的字段再次整理时显示差异，由用户决定采用，避免整块替换。
- 页面顶部持续说明当前为起草、候选或待保存状态，保存成功后反馈剧本与版本。

## 12. 最终验收清单

- [ ] 只有一句点子的用户，能够直接生成并保存，流程中无需填写角色事件语法。

- [ ] 图文存在关键冲突时，用户能看懂冲突并明确处理。

- [ ] 普通故事稿用户能够确认角色与事件，原台词的遗漏或补写能在生成前发现。
- [ ] 角色改名、事件排序和删除操作保持引用一致，非法输入定位到行且长生成调用次数为零。
