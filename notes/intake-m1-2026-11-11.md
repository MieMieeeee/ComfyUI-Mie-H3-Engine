## 交付内容

### 后端（webapp/services/intake.py 新增 + flask_app.py 路由）

`POST /api/scripts/intake`（action=read，M1 仅此 action）：
- 请求：request_id、revision、action、text、image（data URL）、manual_caption。
- 响应一律回显 request_id 与 revision（前端用来丢弃迟到响应）。
- 读稿分组：observed（只写画面可见事实，提示词强制「图中可见」开头，身份/关系/心理
  一律进 proposed）、proposed（创作建议）、conflicts（图文矛盾逐条：field/image/text，
  服务端分配稳定 id：obs_N/pro_N/cfl_N，各限 10/6/8 条、每条 ≤500 字）。
- 视觉能力三态：无「现有可靠能力信息」可用（mie_llm 平台行无 vision 标记），
  按计划落地为 unknown → 发一次正常视觉请求：成功=supported；错误文本可归类为
  不支持图像（4xx + image/vision/multimodal/图片/图像）=unsupported：
  - 无图注 → 200 + `code=needs_caption`（业务状态，素材保留）
  - 有图注 → 纯文本重读一次（图注进提示词，标明人工来源），`basis=caption`
- 上游错误分类（读连接器包装文本）：timeout / auth(401/403/key) / quota(402/余额)
  / rate_limited(429) / unsupported_image / provider，稳定 code 随响应返回。
- 图片服务端独立验证：魔数嗅探（JPEG/PNG/WebP；SVG/伪造类型 → 415「重新选择」）、
  Pillow 实际解码、解码像素 ≤2000 万（→413）、请求体 ≤8MB（→413）。
- 异常模型回复 → code=bad_reply（反馈到当前步骤，不吞字段）。
- 落库不变：read 前后资产清单一致（有测试）。

### 前端（scripts.html + app.js + app.css）

- 「✨ AI 起草」入口改为「从图片或文字起草」卡片；「✨ 修订」保留原卡片（仅 revise）。
- 步骤状态机：material → reading → understanding → generating → candidate；
  素材区（文字 + 单图上传/替换/删除 + 图片用途固定说明）、文字规则（M1 只展示已兑现的
  「允许改编」）、理解确认（observed/proposed 逐条改/删/加，改过即确认）、
  图文冲突逐条裁决（以文字为准 / 以图片为准 / 手动改写），未全部处理时主按钮禁用并说明。
- 浏览器侧图片归一化：EXIF 方向 → 最长边 2048 → JPEG 逐级压缩至 ≤4MB；
  原图 >10MB / 非 JPEG-PNG-WebP 拒绝。服务端照旧独立复验。
- 单主按钮随步骤变化（解读图片 / 生成分镜草稿 / 按图注解读 / 先处理上面的图文冲突 /
  载入编辑器 / 取消等待）；次按钮（先看看 AI 的理解 / 返回修改素材 / 再生成一版）。
- 请求版本保护：revision 随素材/理解/参数变化递增；requestSeq 只认最新；
  取消使在途请求作废（文案说明服务端调用可能已产生费用）。
- 候选保护：编辑器干净且 revision 未变才直接载入；否则停留候选区
  （说明「未保存的改动 / 素材已改过」），载入前走既有 confirmDiscard。
- concept 组织：原文 + 确认摘要（observed/proposed）+ 冲突裁决说明 + 图注（人工来源）
  → 既有 concept 生成（不新增生成路径）。
- 浏览器暂存 `storyboard-intake:v1`：元数据（文字/规则/理解/参数/步骤）写 localStorage，
  图片 Blob 写 IndexedDB（先图后元数据）；失败显示「本次内容尚未暂存」；
  7 天清理；刷新后横幅提供「继续草稿 / 清空草稿」，图片丢失时文字和理解仍可恢复并明说。
- 起草会话保存转正（markSaved 且 intakeLoaded）后会话与暂存一并收摊。
- 可访问性：标签独立于占位符、aria-label 标到条目、键盘可操作原生控件、
  错误文字化、390px 无横向滚动（有测试）。
