## 1. 总体判断

图文起草的入口、解读、事件表单、共享契约校验和显式保存已经落地。事件源确实进入 script 模式，用户能够在生成前编辑确认稿。参考资产保存也有独立入口。

完整可用性仍有断点。当前运行实例尚未加载这批后端和模板。最新版中，图片引导路径、角色确认显示和刷新恢复存在可复现问题。角色音频、场景资产以及制作前准备检查也尚未形成完整的使用闭环。

## 2. 必须先处理的功能问题

### F01 · P1 · 当前运行实例混用了新静态资源与旧后端、模板

在 8199 打开剧本页，点击“AI 起草”没有出现表单。该实例返回的 HTML 不包含 `intake-card` 和 `intakeResume`，所加载 `app.js` 与磁盘新版内容一致。对新增 intake 接口发送空 JSON，8199 返回 405，最新版隔离实例返回正常的参数校验 400。

用户看到的是已有按钮，点击后却无法进入新流程。应先对齐实际启动实例，再建立发布校验。推荐健康接口返回进程启动时的版本标识，静态资源带匹配版本，启动后检查新路由和关键模板标识。

验收应从实际工作台地址点击进入起草，再完成一次确定性角色事件解析。页面、后端和资源版本需要能够核对。

### F02 · P1 · 事件确认页显示的说话人与解析结果不一致

输入两行“小明：今天一起出去走走吗？”和“小红：好，我们出发吧。”，选择“一起设计”，整理后两个事件的角色下拉均显示“1·小明”。服务端返回第二条的 `role_ui_id=r2`，角色列表中 r2 是小红。

页面使用 `:value` 绑定 select，选项又由内部 x-for 创建。需要在选项就绪后保证选择值与事件角色一致。用户确认时依赖屏幕显示，角色显示错误会使确认稿失去可信度。

验收同时比较可见选项、表单值和提交事件，覆盖初次整理、刷新恢复、角色重排和事件复制。后端解析结果正确，浏览器显示错误已独立复现。

### F03 · P1 · 图片理解没有接入一起设计的事件整理

仅上传图片，选择“一起设计”，完成解读后点击“整理角色与事件”，页面报“文字是空的：写一段故事再整理。”。解读中已经有可见信息和创作建议，用户仍需另写文字。

原因是 `intakeStructure()` 要求 `s.text` 非空，并且 events 请求只发送原始文字。有图有文时，确认过的图片信息、用户改写和冲突裁定也不会传入事件整理。

修复时应提交结构化的已确认理解与冲突裁定，保留原文用于台词保护。不要把图片事实和创作建议无差别拼成锁定台词。

验收覆盖纯图片、图片加文字、人工图注和手动裁定冲突。用户确认的信息应能在下一步的角色、事件或设计字段中找到对应。

### F04 · P2 · 刷新恢复事件草稿后一直显示预检中

角色事件整理通过后刷新，点击“继续草稿”，角色和事件恢复，但主按钮一直为禁用的“预检中…”。等待后仍不恢复。手动点击“重新预检”才能继续。

### F05 · P2 · 返回修改素材会直接清掉人工编辑过的事件稿

事件页的“返回修改素材”直接执行 `s.eventDraft=null` 并更新暂存。用户改过的角色、台词、事件顺序和补写采用状态随之丢失，之后整理只能从原文重新开始。

返回上一步应保留事件稿并标记需要重新确认。再次整理时展示差异，让用户决定采用。只有用户明确选择重新开始时才清空。

### F06 · P1 · 另存参考资产可能静默覆盖同名资产

M3 保存直接将填写的名字提交到现有 upsert 接口，没有同名确认或创建专用语义。临时资产库验证同名提交返回 `status=overwritten`。新建入口的用户容易把“另存”理解为新增。

新建或另存流程应明确处理重名，默认提示改名。允许覆盖时展示将替换的资产及受影响的引用，再由用户明确选择。服务端也应支持创建时拒绝重名，避免只靠前端检查产生竞争窗口。

验收要求同名角色和场景均不能被新增流程静默覆盖，原有媒体和描述在用户决定前保持可恢复。

## 3. 必须补齐的用户便利性

### U01 · 角色音色试听需要覆盖三个位置

当前角色详情只有声音描述和样本数量，API 也只返回 audio_count 与 audio_exts，没有可播放的音频地址。编辑页选好音频后仅显示文件输入。制作页选角只展示图片和描述。三个位置都缺少声音确认。

建议作为一项完整功能交付。

1. 资产详情展示每段样本的播放器、序号和时长，支持暂停、进度定位与重新播放。多样本应全部可访问，并明确实际使用哪个样本。
2. 上传后先本地试听，展示将替换哪个样本，用户保存前能发现选错文件。切换资产或替换文件时停止旧播放。
3. 制作选角卡同时展示立绘、声音描述与试听入口。参考配音时直接在这里核对人脸和声音。

只有声音描述时显示“暂无声音样本”，提供上传入口。文字描述本身无法给出已经确定的声音。未来若接入模型试听，应展示生成按钮、试听文本、实际调用方式和用量提示，并标明试听与最终生成的关系。

验收覆盖已有样本、新上传、多样本、无样本、播放失败、切角色和选角试听。同一时间只播放一个样本，自动播放保持关闭。

### U02 · 场景资产需要进入制作流程

场景可以创建、保存，也能从起草图片另存，但视频页只有角色选择。workflow.build 也只为角色创建加载节点，没有把场景选择传给计划节点。计划预览可显示 scene_1 未接线，页面却没有对应操作。

### U03 · 图片预览、替换和媒体改动保护需要一起完善

详情固定展示第一张小图，虽然接口返回完整 images 数组，页面缺少浏览全部图片和放大的入口。编辑表单选择新图片后缺少明确的新旧对照。新建资产仍使用“留空则保留原图”的帮助语，无法表达首次创建所需媒体。

资产页的 isDirty 只比较文字表单，忽略 imageFile 和 audioFile。只替换媒体后切换资产或离开页面不会触发这份保护，待上传文件会丢失。

应提供缩略图组和放大查看，新旧媒体预览，以及创建与编辑分别适用的必填说明。将媒体选择、删除和替换纳入改动状态。

### U04 · 保存、制作与返回应能连续完成

编辑器有未保存修改时，“用此剧本制作”仍指向已保存的 selected。当前离开页面保护会提示丢弃，但用户要渲染刚改的内容时，还要理解保存版本与制作入口的关系。建议将主动作变成“保存并制作”，保存失败留在当前稿，成功后明确使用的版本。

制作页修改角色绑定后，没有“去资产页补声音，再返回继续”的会话恢复。loadScript 每次把所有 asset 清空。应暂存本次制作配置，返回后恢复剧本版本、角色和场景绑定、画幅及参数，并提示已失效资产。

历史页应提供“用本次配置再做一版”，按新运行名创建新版本。当前“从这次继续”保留续跑含义，并说明复用的输入是否仍可取得。

### U05 · 起草参数应显示真实生效值

起草表单默认 shot_count 为 0，字段只写“希望切成几镜”。直接 concept 请求又执行 `Number(s.form.shot_count) || 2`，所以用户看见 0，实际提交 2。script 路径则保留 0 表示自动。

应把“自动”做成明确选项，在两条路径保持一致。若概念模式确实需要固定默认值，页面就展示该值。生成前摘要应说明时长与分镜数当前属于偏好还是固定条件。

“一起设计”可增加可编辑的一句话故事摘要，让用户先核对这一版在讲什么，再进入角色和事件。整体画面设置中的英文术语应配中文用途说明。

### U06 · 历史记录应帮助用户辨认作品与版本

运行中历史列表的同一个 run_name 有多条尝试记录，分别标为中断或完成，并显示相同成片链接。这与共享运行目录的继续执行有关，但用户难以判断哪个结果属于哪次尝试。

建议按作品运行聚合尝试记录，成片归到所属运行，展开后查看尝试时间和状态。保留版本、收藏和下载入口，补充剧本或作品搜索。声音文件可在当前记录内试听，分镜片段可在当前页切换播放。

现有成片播放与下载入口清楚，播放器按需创建，也已区分移出列表和删除文件，这些行为应保留。

### U07 · 模型设置与起草入口应互相接上

模型设置页集中展示 23 个平台，已有搜索和连接测试。起草区缺少当前模型、连接状态和视觉能力提示，用户容易到解读失败时才发现设置问题。

建议在起草卡片展示当前平台和模型，以及已知或待确认的图片能力。未配置时提供直达设置的入口，返回后保留素材。首次使用可引导先完成一个平台配置，再展开完整平台表。

### U08 · 窄屏打开编辑任务时应把操作区带到用户面前

390 像素宽的起草页没有整页横向溢出，但剧本列表、语法说明和恢复卡片都在表单前。即使测试库只有两个剧本，AI 起草表单也已靠近首屏底部。

打开起草或编辑后滚动到操作区并设置合理焦点。窄屏将剧本列表折叠为选择器，恢复卡片提供简洁的一行摘要。事件列表保持逐行操作，并在关键动作后保留用户位置。

## 4. 页面覆盖结论

| 页面或流程 | 已具备的能力 | 本轮主要缺口 |
| --- | --- | --- |
| 大模型 | 搜索、模型选择、密钥保存、测试 | 当前模型与起草衔接、初次配置引导 |
| 角色与场景 | 分类、图片、编辑、AI 补全 | 音频试听、全图浏览、媒体改动保护 |
| 图文起草 | 素材、读稿、来源分组、冲突处理 | 图片进入引导路径、保留用户已编辑事件 |
| 事件确认 | 确定性解析、行编辑、共享预检 | 角色显示一致、刷新后自动预检 |
| 剧本编辑与版本 | 预览、表单、版本与恢复、执行描述 | 保存并制作、确认稿变化的清楚交接 |
| 视频制作 | 剧本内容预览、角色图像、运行名 | 声音检查与试听、场景绑定、配置恢复 |
| 制作历史 | 分类、成片播放下载、收藏、续跑 | 尝试与作品归属、同配置新版本、搜索与声音试听 |

## 5. 建议实施顺序与验收包

1. 先对齐实际运行版本，修复角色显示、图片引导、恢复预检和返回丢稿。
2. 补齐资产详情、上传后和制作选角三个位置的试听，同时加入媒体改动保护和参考配音准备检查。
3. 修复 M3 同名覆盖与目标丢失，接通场景资产到制作计划。
4. 完成保存并制作、制作配置恢复与同配置再做一版，再整理窄屏和术语。

第一批页面回归至少包括双角色初次显示、图片无文字引导、事件页刷新恢复、修改事件后返回、只换音频后离开、无声音资产的参考配音、同名另存和参考目标读回。测试应同时检查可见控件、提交数据和读回结果。

模型实际识图质量、声音样本与最终配音的一致性，以及场景引用后的真实渲染效果，需要使用已配置平台做独立端到端验收。本轮受控模型回复用于验证页面和数据流。
