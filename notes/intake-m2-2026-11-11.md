# 图文起草 M2 实施记录 · 2026-11-11

对应计划：docs/plans/2026-11-11-storyboard-intake-plan.md（§9 M2，核心功能对外完整发布点）。
基线：提交 7408ea8（M1）。

## 交付内容

### 后端（webapp/services/intake.py + autodraft.py 重构 + flask_app.py 路由）

`POST /api/scripts/intake`（新增 action=events）：
- **确定性快速路径**：整篇已是角色事件行的文字（每行 `名字 [类型] [zh|en]：内容`）直接
  走共享 `parse_roles`/`parse_script` 解析（`mode=parsed`），零模型调用、零改写；
  每条事件带回原文整行 span；角色标签行不算未分配内容，注释行不算内容。
- **普通文本**：专用提示词（roles 1..8 / events 1..200 / source 逐字摘录 / 补写留空）
  → 严格逐字段校验（角色引用序号、类型枚举、非空文本、语言）→ `mode=proposed`，
  每条事件带 span 映射；source 在原文中找不到的按无映射处理；
  没被认领的原文片段单独返回（unmapped）。
- 模型回复字段类型/枚举/引用不符 → `code=bad_reply`（回到当前步骤，不吞字段）。

`POST /api/scripts/intake/validate`（无模型）：
- 复用 autodraft 的序列化（`_role_settings_line`/`_event_line`，M0 抽出的
  `_round_trip_problems` 现在供两条路径共用，错误带 event_index 定位到行）。
- header 契约用与生成器完全相同的 probe（`validate_v2(_check_timing=False)`）：
  camera 枚举、light、scene、name、时长范围、shot_count（0=自动，否则 1..20 且 ≤事件数）。
- **可证明的时长冲突**（分组不存在时也成立的算术）：`estimate_shot_seconds` 对事件
  可加——单条估算 >30 秒（任何镜都装不下）逐条报；全部事件内容下限减去
  20 镜×22 帧重叠的最多抵扣（≈18 秒）仍 > 目标时长则报总量冲突。
  估计性的界限留给生成后的完整校验（计划 §6.3 的"真实适用范围"）。

### 前端（app.js + scripts.html + app.css）

- 素材卡片新增：**生成方式**（直接出一版 / 一起设计）、**文字规则**（允许改编 /
  保留原台词）。原文每行都像角色事件行且用户未手选规则时，自动预选
  「保留原台词」并显示已识别行数（计划 §2）；手选后以用户为准。
- 步骤状态机扩展 `events`（第 3 步·角色与事件）：
  - 角色卡（名字/画面内外/位置/声音说明，映射角色契约；删被引用角色被阻止并说明）；
  - 事件行（角色下拉/类型/内容/语言 + 上移下移/复制/删除/新增；aria-label 逐行）；
  - 事件引用角色序号——重命名自动同步（§5）；
  - 未分配片段卡：加成一条事件 / 记为场景说明 / 解除保留，三条出路；
  - 模型补写默认不参与生成（「补写，确认采用」勾选才进确认稿）；
  - 「整体设计」区：scene/setting/look/constraints + 默认景别/运动/视角
    （script 模式将锁定的全局 header，帮助文字说明字段用途）。
- 预检：事件稿变化后 700ms 自动重查；生成前**强制**服务端重验（前端标记不作数）；
  预检错误定位到行（红框 + 行内消息），未处理片段/补写/预检失败都会阻止生成并说明。
- 生成路径分发：`direct+adapt` → concept（M1 行为不变）；
  `keep` 或 `guided` → `/api/scripts/auto` mode=script（M0 的锁定路径）。
- 取消/迟到保护扩展到 events 步骤（genFrom 记录发起步骤；预检用独立序号，
  不抢占请求序号——生成流程内部的重验不会作废在途生成）。
- 暂存扩展：flowMode/textPolicy/eventDraft/design 一并进 `storyboard-intake:v1`。
- 编辑器集成（§7）：script 路径草稿载入时记录确认稿指纹，编辑器顶部说明
  「按 N 条已确认事件逐字生成」；事件被改过后改为警示「确认稿已偏离，保存的是改后内容」。

  未单独提出「一句话故事」字段（计划 §3.3 的建议性内容由整体设计区承载）。
