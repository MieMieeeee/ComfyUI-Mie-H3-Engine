# 项目设计与界面审查 · 2026-11-10

结论：共享核心与引擎分层方向合理；网页端已有完整功能骨架，但创作流程、编辑安全和任务可信度仍需优先完善。当前更接近熟悉内部术语的操作台。

范围：阅读 README、PLAN、webapp 说明、模板、CSS、JS、runner/workflow/comfy 服务及剧本加载节点；启动当前工作区网页，检查四个页面、现有剧本预览与编辑，测试 390×844 窄屏。未执行付费 LLM 请求、保存资产或提交渲染。未全面审计上游生成内核。已有未提交修改保持原样。

**值得保留**
- mie_craft / mie_llm 作为共享契约与逻辑来源，避免网页与节点各自实现一套。
- Flask + Jinja + Alpine 符合 embedded Python 分发约束，当前阶段无需为视觉改造更换框架。
- 剧本的时间轴、事件卡片、目标时长与交付时长对照，以及契约错误与渲染风险分开呈现，有明确业务价值。

**P1：切换剧本直接丢失未保存修改（浏览器复现）**
在“下班前上线”的编辑页，将画风临时改为 REVIEW_UNSAVED_PROBE，再点击另一份剧本。没有确认提示，编辑模型直接被替换。临时内容未保存到资产库。
位置：webapp/static/app.js:542；startNew:560；save:1009。jsonDirty 只追踪源码解析，不代表整个文档的未保存状态。
建议：保存基线快照，统一计算 dirty；切换、新建、导航、关闭页面均保护草稿；增加本地恢复和明确的已保存状态。

**P1：排队任务没有固定剧本版本（源码确认，未实际排队复现）**
runner 读取剧本后，workflow 向队列传递的仍是 name，加载节点在执行时重新读资产库。排队期间同名剧本修改后，实际生成内容可能与提交时预览不同，角色顺序也可能发生变化。
位置：webapp/services/runner.py:98；webapp/services/workflow.py:89；mie_nodes.py:70。
建议：提交时固定剧本、角色资产及生成参数的不可变版本/内容哈希；执行读取快照，任务详情保留这些版本信息。

**P1：磁盘残留片段被直接称作 running（源码确认，页面可见旧任务仍为 running）**
recent_runs 仅凭存在 segments、缺少 final 就设 running；jobs 将该结果直接合入页面，未核对对应任务的队列。另一方面，job 将 pending 和 running 合并成一个集合，也会把排队中标成运行中。
位置：webapp/services/comfy.py:251；webapp/services/runner.py:142、200。
建议：区分排队、运行、等待审核、已中断、部分产物、完成与未知；磁盘产物只能证明有结果，不能证明仍在执行。

**P1：制作前置条件没有反映在按钮状态中（浏览器复现）**
选择“小兔子问幸福-单资产”，六个角色资产均为空，“开始渲染”仍可点击。预览出错被静默清空，提交期间也无 submitting 防重复状态。后端仍有角色必填守卫，本次未点击真实提交。
位置：webapp/templates/video.html:68；webapp/static/app.js:1221、1243；webapp/services/workflow.py:98。
建议：显示每个角色的缺项；预检通过才允许提交；提交中锁定按钮；后端加幂等控制。

**P2：桌面表单溢出，窄屏导航与标题失去可读性（浏览器复现）**
桌面制作页左栏已有横向滚动条，四个数字输入挤出容器。390px 视口下，大模型页 documentElement.scrollWidth 为 748px；导航与标题被挤成逐字竖排，路径文本向外延伸。
位置：webapp/static/app.css:42、103、156、178、219；模板 panel-head-actions 中的长路径。
建议：统一 border-box；flex/grid 子项设置 min-width:0；参数改成两列；页头换行；长路径收进详情；窄屏导航采用横向滚动或菜单。

**P2：主流程按数据类型拆开，用户缺少下一步入口**
剧本预览上提供修订、校验、保存和删除，没有“用此剧本制作”；切到制作页还要重新选择剧本、逐个从长名单匹配角色。资产页也只有文字名单，无搜索或缩略图。
位置：webapp/templates/scripts.html:172；webapp/templates/video.html:24；webapp/templates/assets.html。
建议：保留四页能力，补“当前作品”上下文及“剧本 → 配角色 → 检查 → 生成 → 成片”的连续动作；支持带 script 参数进入制作；资产选择显示缩略图、音色试听和名称匹配建议。

**P2：中文创作与英文 execution 的编辑责任不清楚（源码确认）**
表单同时展示源语言和英文执行镜像。afterModelChange 只同步事件/键并校验；已有 directions 直接保留，look、setting 等也不会随源字段自动更新。普通用户可能修改中文设定后仍带着旧执行文本提交。
位置：webapp/static/app.js:631、693、880；webapp/templates/scripts.html:481。
建议：以中文创作为默认编辑面，execution 放到高级面；标记过期的执行镜像并提供显式重新生成/人工确认动作，不应静默覆盖人工英文修改。

**P2：模型设置密度高，表单可访问名称不足（浏览器与源码确认）**
所有平台以长表展示接口、模型、Key、操作；当前平台位于列表中段；原生 select/input 缺少关联 label 或 aria-label，模型与密钥控件难以被辅助技术区分。
位置：webapp/templates/llm.html:26、47、72。
建议：置顶当前平台，其他平台可搜索并按需展开；接口等技术信息放进高级配置；为每行控件添加包含平台名的标签。

**视觉判断**
深色绿色主题整体统一，主按钮有明确强调色，适合作为长期使用的制作工具。主要问题是层级与信息密度：大量 11–13px 辅助文字、相近底色的面板层层嵌套、多个刷新按钮和大段内部术语挤占创作空间。
建议：保留现有主题，减少一层容器；强化“作品名、当前阶段、下一步动作”；把库路径、节点类名、socket、编译契约说明收进技术详情；任务以作品名、时间、阶段、预览和恢复动作呈现。

3. 打通从剧本直接制作、可视化配角色、任务预览与恢复。
4. 再处理字号、容器层级、文案和模型设置密度。
